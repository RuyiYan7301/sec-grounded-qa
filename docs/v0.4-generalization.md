# v0.4 generalization test: the v0.2 rules on 77 new companies and FY2019-FY2022

Protocol: `docs/v0.4-plan.md` section 2 (committed before any download). Everything here is measured with
the frozen v0.2 ontology, fact store and resolver, before any fix. Reviewers are Claude sub-agents (model
review, not human review), one per packet of 50 cells, with access only to the packet and the 10-K text;
they did not see the concept the engine used.

## 2a. Data layer

### Coverage (all cells; `results/v0.4/coverage/`)

77 new filers x 23 metrics x FY2019-FY2025 = 12,397 cells:

| status | cells |
|---|---|
| resolved | 9,705 |
| fallback with scope warning | 282 |
| ambiguous concept (engine abstains) | 45 |

The 8 original filers, now FY2019-FY2025: 1,171 resolved, 14 fallback, 103 not reported.

Most `not_reported` cells are lines a company does not present: gross profit 340/527 company-years,
operating expenses 419/527 (many income statements show "total costs and expenses" instead), long-term

The pre-set threshold (0.90) is met, so step 2 is not delayed.

Silent errors:
- **operating_expenses** (GM FY2022, CAT FY2019): both filers tag "total costs and expenses", which
  includes cost of sales, with `OperatingExpenses`. The ontology's primary concept is the filer's tag, so
  the value is the tag's, not the metric's definition. 3 of 5 operating-expense cells correct.
- **cost_of_revenue** (UNH FY2023): `CostOfGoodsAndServicesSold` is products only; UnitedHealth has no
  total cost-of-revenue line (medical costs are separate).
- **long_term_debt** (GD FY2022): 10,590 vs the 10,496 the reviewer read as total debt; not resolved
  further.

Unverifiable: 3 IBM cells. IBM's 10-K incorporates the financial statements by reference to the annual
report exhibit, which the text conversion does not include.

Not-reported cells that the filing does print (7): 5 are long-term debt, where the 10-K prints a total
(current plus noncurrent) in the debt note but the XBRL facts carry only the noncurrent or current
portions, which the ontology treats as confounders (the v0.2 notes already list this for ORCL, AMD and
AVGO); 1 is GM's automotive cost of sales (reviewer unsure; excludes GM Financial); 1 is Netflix debt.

### Fiscal-year labels (`results/v0.4/coverage/labels.json`)

The engine names a fiscal year by the calendar year it ends in. Three new filers name theirs differently,
for every year:
- **HD, LOW**: fiscal year ending around 1 February is named by the year it starts (Home Depot's "fiscal
  2024" ended 2 February 2025). The engine calls it FY2025.
- **JNJ**: 52/53-week year ending on the Sunday nearest 31 December. When it ends in late December (29
  December 2019), the engine's rule (nominal year end 3 January + 7 days) gives the next year: FY2020 for
  Johnson & Johnson's fiscal 2019. This is a defect of the rule, not a naming convention.
- CRM: one 10-K (FY ending 31 January 2026) whose DEI focus disagrees with the other years; not a pattern.

Because gold labels and engine labels use the same rule, the end-to-end test (2b) cannot detect this; it
is reported here instead. A user asking for "Home Depot's fiscal 2024 revenue" gets the wrong year today.

### Frames cross-check (`results/v0.4/frames/`)

Six metrics, all 85 filers, FY2022-FY2024, same concept and period: 1,168 agree within 0.5%, 19 disagree,
253 periods appear in no calendar frame. All 19 disagreements are frames values taken from proxy statements
(DEF 14A pay-versus-performance tables, which report net income including noncontrolling interests, and in
three filers a value tagged without its scale); the store, which reads 10-K rows only, matches the 10-K in
each case.

### Other finding

The SEC submissions file lists only the latest ~1,000 filings; older filings are in extra pages. The v0.2
Part B code (`resolve.FilingFactIndex`) reads only the first page, so for filers with many filings
(VZ, WMT: three 10-Ks visible) older 10-Ks are invisible to it. The coverage script reads all pages.

## 2b. End-to-end (`results/v0.4/pipeline/`)

160 generated questions on 68 new companies, FY2019-FY2025 (seed 2606, committed in `bd1fb7d` before the
run); frozen planner prompt with only the ticker list, names and years generated from the universe
(prompt sha256 `494c65126ed9...`, identical to the saved `planner_prompt_v04.txt`); `qwen3:8b` (digest as
in v0.2, Ollama 0.34.0); frozen scorer 2.1. Runner `evaluation/v4/run_2b.py`, committed before the run.
A dry run with the gold plans executed 160/160 correct, so harness and gold agree.

| | v0.4 new companies (160) | v0.2 test, generated layer (80, original companies) |
|---|---|---|
| plan valid | 158 | 80 |
| execution correct | 154 (96.3%, Wilson 92.1-98.3%) | 80 |
| **final correct** | **144 (90.0%, Wilson 84.4-93.8%)** | 80 |
| execution right, rendered answer scored wrong | 10 | 0 |

Different companies, years and item counts; the comparison shows a drop, not its exact size.

By intent (final correct): fact lookup 39/40, multi-period 16/16, cross-company 19/20, absolute change
19/20, percent change 21/24, percentage-point change 11/16, ratio 10/12, restated value 9/12.

Noise: the 40-item rerun (ids fixed by `random.Random(2606)` in the runner) gave identical plans and
identical correctness on all 40; 19 of 40 rendered texts differ in wording.

Planner failures (6):
- **R&D intensity read as gross margin, 3/3**: every "R&D as a share of revenue ... in percentage points"
  question (ISRG, PLTR, CRM) got `metric: gross_margin`, while the plan's own `assumptions` field names
  `rd_intensity`. The same template on Apple and Intel in the v0.2 test was planned correctly. The one
  `rd_intensity` ratio question here was right. Cause not established.
- **Gross margin asked, gross profit looked up** (COST): a ratio question planned as a fact lookup.
- **Restated-value plans invalid, 2/12**: the model wrote `periods: ["FY2020", "FY2020"]`, which the schema
  forbids (`uniqueItems`). The planner decodes under the schema (Ollama structured outputs), so this shows
  the constraint is not fully enforced; the one repair call repeated the same plan.

Renderer losses (10, execution right): 7 answers state a number the scorer reads as contradicting the
result, and 3 not-meaningful answers are worded in a way the scorer does not accept. In 5 of the 7, the
answer also discusses a restatement or revision warning (earlier-reported values). These 10 answers have
not been read one by one yet; until they are, they are counted as wrong, as the frozen scorer says.

What 2b does not measure: gold uses the same ontology and fiscal-year rule as the engine, so the 2a
findings (operating-expense tags, HD/LOW/JNJ fiscal labels) do not show up here.

Run history: a first launch was stopped at item 17 when the session ended (no result file; log kept as
`run_2b_main_interrupted_at17.log`), and a second failed at item 1 because Ollama was not running
(`failed_launch/`). The reported run is the third, complete, launch.
